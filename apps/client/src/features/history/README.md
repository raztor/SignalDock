# Communication history

`HistoryScreen` accepts the common `FeatureScreenProps` and must render inside `StationProvider` (radio names) and, ideally, `ToastProvider` (operation results). It shows:

- **Activity heatmap** (`ActivityHeatmap`): 7 days × 24 local hours from `GET history/activity?days=7&tz=<IANA>` (scoped by radio, frequency and direction like the timeline). Tapping an hour sets a "Before <hour end>" filter (removable chip) and scrolls to the timeline. Each cell is labelled, e.g. "Tuesday 21:00, 12 communications". On phones the hours scroll sideways so each cell is a 32 pt square (36 pt with slop) while the day labels stay put. On web the grid is a single Tab stop (`role="grid"`): arrow keys move by hour and day, Home/End jump within the row. Local hour boundaries follow daylight-saving changes (`zonedTime` picks the earliest instant of a repeated hour and the transition for a skipped one). A polite status line announces the result count after each search or filter change. Without the route the heatmap is replaced by a short note.
- **Timeline** (`CommunicationRow`): direction icon (RX, TX, TTS, digital, note), local time, duration, frequency chip (dashed when the source is inferred or unknown), `Waveform` peaks from `GET communications/:id/waveform?points=64` (TX in the on-air tone; loaded at most four at a time and cached per communication; a flat duration bar when peaks are empty, the request fails or the route is missing), inline transcript (latest revision, expandable), notes, tags and the private `RecordingPlayer`. Day headings separate local days.
- **Overflow menu** per row: transcript provenance (all revisions), add/correct transcript (`history.write`), hold/release retention and delete (administrators). Deletion stays disabled while a retention hold is active and always asks for confirmation.
- **Coverage gaps** (`CoverageGapRow`): hatched, dashed rows "No coverage 21:44 → 21:58 · reason" placed chronologically, derived from `GET radios/:id/coverage` when one radio is in scope. An unmonitored gap is not evidence that no traffic occurred.
- **Filters** (`HistoryFilterBar`): live search (350 ms debounce, Enter applies immediately), direction chips (All / Received / Transmitted / Notes / Digital), frequency groups, and date range chips (Today / 24 h / 7 days / All). Digital and date ranges filter loaded pages on the client; paging stops once the range start is passed.

Pure logic lives in `history-model.ts` (tested in `history-model.test.ts`); HTTP calls in `history-api.ts`. The screen stays mounted while other sections are visited, so filters, search text, pages and scroll position are retained.

Web playback fetches with the selected instance's authorization header, creates a temporary object URL, and stops/releases it on session change or unmount. Native development builds use the SDK58-compatible `expo-audio` adapter with authenticated source headers. No token appears in a URL. Native playback still requires physical development-build acceptance; background playback is not enabled here.

The workspace remounts when the instance or credentials change, cancelling reads and discarding prior cached communications and waveforms. Client visibility is advisory; the backend authorizes each operation. Station notes are archive-only and never transmitted.
