# Identity implementation handoff

The backend exports `IdentityService`, `SqlIdentityRepository`, `identityMigrations`, `registerIdentityRoutes`, and `createArgon2idHasher` from its domain index. Apply migration `010_identity` after the shared foundation migration. The production repository scopes every query and foreign key to its instance.

Dependencies: `@node-rs/argon2` 2.2.2 and `@signaldock/database`. Root composition supplies the actual database, persistent instance ID, setup token (at least 24 characters), permitted same-origin cookie origin, and revocation callback. Bootstrap creates no implicit radio permissions.

Access/session revocation is database-authoritative, and refresh reuse is committed before its error is returned. Login rechecks a locked user record after password verification; password, grant, and administrative-session changes invalidate pending logins through the user authentication version. Concurrent user edits acquire the same row lock. Radio/PTT/media invalidation must be connected by composition; the module never contacts a radio itself. Global `instance.admin` does not confer operational radio permission.

The frontend exports `SessionController`, `createPlatformAuthOptions`, `useAuthSession`, `LoginScreen`, `BootstrapScreen`, and `SessionListScreen` from `apps/client/src/features/auth/index.ts`. `UserAdminScreen` is exported from its administration feature. The shell constructs one controller, supplies `onContextChanging` to stop PTT/media/subscriptions and clear account caches, and passes the controller's `ClientSession` snapshot to domain screens. Server selection calls `selectServer(baseUrl, info)` followed by `restore()`; recent-server removal calls `forgetServer(recentServer)`. The shell owns global navigation and disposal.

Client dependencies are Expo SecureStore 58.0.2 and Expo Crypto 58.0.7. Same-origin web uses cookie refresh plus CSRF; remote web keeps bearer refresh credentials in memory. Native refresh storage is scoped by URL, instance ID, and pinned key identity with device-only accessibility. Access tokens/passwords are never saved. Refresh uses a single-flight controller and cookie Web Locks where supported. Context generation, aborts, scoped credential deletion, and access-token-aware unauthorized callbacks fence late responses.

Validation: 18 backend tests against real PostgreSQL 18.4, including concurrent bootstrap/user creation, refresh reuse, verified-login invalidation during password/permission/session changes, absolute token expiry, live authorization, compound instance isolation, browser CSRF, and local recovery; 13 frontend controller tests covering colliding usernames, scoped restore/forget/logout, identity replacement, late login, old unauthorized callbacks, refresh single-flight, and wrong-account rejection. The password adapter test uses actual Argon2id. Fixtures are not hardware, native-device, or external-provider acceptance.

The initial login rate limiter is process-local, so deploy one API process until a shared limiter is added. Native SecureStore and interruption behavior still require development-build/device acceptance. Cross-origin web reload intentionally requires login. Physical radio, store publication, and production Linux device acceptance are outside this module's local verification.
