# Communication history

`HistoryService` provides instance-scoped frequency conversations, recording metadata, immutable transcript revisions, source validation, coverage intervals, retention, and audited corrections. This package contains no public routes or device-specific protocol.

Compose `historyMigrations` after database/identity/radio migrations. `020_history` creates `sd_communications`, `sd_recordings`, `sd_transcript_revisions`, `sd_frequency_conversations`, `sd_history_audit`, and `sd_coverage_intervals`. A radio and integer frequency identify a conversation; unknown attribution uses the radio's unknown-frequency conversation. The original capture context is preserved, even when an operator corrects its frequency classification.

`ingest(input, audio?)` accepts a finalized capture. Recording storage failure or quota exhaustion creates an explicit gap entry while preserving the communication. Re-delivery with the same identifier is idempotent; changing the capture or bytes is rejected. Files are private artifacts and never publicly mounted. `readRecording()` supports byte ranges after callers authorize the returned radio scope.

`appendTranscript(instanceId, communicationId, input, transaction?)` locks the communication, verifies `expectedRevision`, appends an immutable transcript, and advances the communication revision. Use the supplied transaction from a job's terminal `execution.commit()` to atomically fence late results. `validateJobSource(job, tx)` takes the communication lock before the recording lock; all source writers use this order.

Deletion tombstones the communication, cancels queued/running work, removes unheld derived text, and makes artifacts unavailable before deleting files. Failed file deletion remains durable in recording metadata; schedule `cleanupDeletedArtifacts()` regularly. `applyRetention()` has separate audio, transcript, and full communication cutoffs. Explicit communication holds and incident evidence holds block retention. Operator annotations, classification changes, and deletion are audited. Retention removes derived analysis/evidence quotes when no hold applies.

Create coverage intervals only when a radio generation and tuning context is observed, close them on tuning/disconnection, and never infer monitoring of other frequencies. A current dashboard frequency cannot establish a previous recording's source.

`HistoryCaptureRecorder(history, options)` accepts synchronous `push(frame, context)` calls and exposes asynchronous `flush()` / `stop()`. Frames are copied before returning. RX uses configurable PCM energy segmentation with pre-roll, hang time, an idle timeout, and explicit driver burst endings; TX records accepted microphone and TTS frames. Revision, generation, stream, and sequence discontinuities split segments. WAV captures carry original source metadata. The bounded queue reports drops through `onError`, and the next accepted segment declares the lost count; capture cannot block live control. `onFinalized(communication)` schedules optional processing after persistence, with the finalized communication's revision and artifact reference. A storage gap must never be submitted for speech processing.

Wire `HistoryOptions.onDeleteSource(tx, {instanceId, communicationId, artifactIds})` to installed derivative modules such as digital packet storage. The hook runs under the source transaction and removes recording-derived packets/positions before full deletion or audio retention. Handler registration is owned by application composition. The shared `createHistoryMaintenanceHandler()` supports bounded independent retention and durable artifact cleanup; both API composition and the standalone worker import it from this package. Schedule it only from trusted administration. Its repeated side effects are idempotent.

Wire the separate optional `HistoryOptions.onDeleteTranscripts(tx, {instanceId, communicationId})` to processing-source cleanup. Transcript-only retention invokes it while holding the communication lock, before removing transcripts and incrementing the source revision. Purge copied processing requests, results, and shared job outputs in that same transaction, with shared job locks preceding domain-row locks. Do not call recording/digital cleanup from this hook: playable audio and its recorded-packet evidence remain available when only text expires. A callback failure rolls back the complete retention change.

The transcript-retention regression uses PostgreSQL 18, actual processing/shared-job tables, private file storage, a processing-purge SQL composition stand-in, and a recording-derived digital evidence probe. It proves callback ordering, the source lock, retained audio, copied-text removal, and rollback. Application integration must additionally verify the production processing cleanup helper is wired to this hook and the actual digital packet/position rows survive text-only expiry.

Run the real PostgreSQL integration suite with `TEST_DATABASE_URL=... npx vitest run packages/history/test`. Each run creates and removes its own schema. PostgreSQL 18 is required; fixture-only tests are not database acceptance.
