# PostgreSQL persistence

`PostgresDatabase` implements the shared `DatabasePort` with node-postgres. Transactions keep one checked-out connection; nested transactions use savepoints. `close` drains the pool and `health` reports connectivity without exposing connection details.

`migrate` applies sorted `{ id, sql }` migration providers inside an advisory-locked transaction. IDs use `000_name`; applied SQL checksums are immutable. Domain modules contribute their own arrays and application composition registers them. `foundationMigrations` owns the job ledger and transactional event outbox. `appendOutbox(tx, event)` inserts alongside domain writes; `dispatchOutbox` supports multiple consumers with row locking and at-least-once delivery.

Station-specific dispatchers must call `dispatchOutbox(database, deliver, limit, instanceId)`. The UUID scope applies in the locked selection before pagination and preserves other stations' undelivered events, including colliding event identifiers. Omitting the scope retains global dispatch for a deliberately shared worker. Reserved `job.enqueue` events remain exclusive to the job publisher.

The exported `OutboxEvent` includes `instanceId`, `id`, `type`, optional `radioId`, `payload`, and canonical UTC `occurredAt`. Delivery callbacks receive `(event, transaction)`, where the second argument is the same transaction that acknowledges the outbox batch. Existing one-argument callbacks remain valid.

For cross-process refresh fanout, construct `PostgresOutboxEvents({connectionString, instanceId, onError?, onReconnect?})`. An API process calls `await broker.start((event, signal) => ...)`; a worker can publish without starting any listener. Inside the dispatch callback call `await broker.publish(event.id, transaction)`. PostgreSQL delivers the notification only when the outbox acknowledgement commits. The notification contains only the instance/event UUIDs; the dedicated listener hydrates the canonical scoped row, including payloads larger than PostgreSQL's notification limit. No audio or public authorization tokens enter the notification payload. Application composition maps the event to public schemas and checks each subscriber's authorization.

`close()` cancels connection/reconnect work, aborts the subscriber signal, drops pending refresh references, and closes its dedicated PostgreSQL connection. Handlers should honor that signal and avoid unbounded work. The queue defaults to 256 references (`maxPendingEvents`, maximum 10000); connection retries use bounded exponential backoff (`reconnectDelayMs`, default 500 ms, capped at 30 seconds). Queue overflow, delivery failure, and disconnect are reported through `onError`. `onReconnect` runs after a successful reconnection, never the first connection; use it to rotate the public refresh generation and close existing event streams so clients reload authoritative state.

This is live refresh fanout. PostgreSQL `LISTEN/NOTIFY` does not replay events missed during disconnection or process restart; there are no durable subscriber offsets. Consumers must resynchronize from authenticated APIs, and retries may repeat an event ID. The broker does not acknowledge, execute, or replay radio commands. Source/domain writes remain in their existing transactions, and the outbox remains the authoritative event record.

Production requires PostgreSQL 18. Integration tests run only with an explicit `TEST_DATABASE_URL`, create a private temporary schema, and remove it afterward. A missing URL means those tests are skipped, never a PostgreSQL acceptance claim.

For development on a machine without containers, run `node packages/database/scripts/dev-postgres.mjs` with Node 24 and npm. It installs the pinned portable PostgreSQL 18.4 development runtime into ignored `.local/pg-runtime`, keeps data in `.local/postgres18`, binds only loopback port 55432, and prints a test-only URL. `SIGNALDOCK_DEV_PG_PORT` changes the port. The runtime is isolated from workspace `node_modules` so ordinary dependency installs cannot remove libraries from a running database. Startup verifies both the server version and PL/pgSQL loading. Stop with Ctrl+C; data persists. Never use these fixed local credentials or this development helper in production. CI and deployed installations use an official PostgreSQL 18 service.
